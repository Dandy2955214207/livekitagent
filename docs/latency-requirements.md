# 时延与通话内需求管理（2026-11-05）

分支 `codex/qwen-live-harness-adapter`。沿用手机页面、LiveKit、百炼实时模型、固定 Qwen Live Harness 1.0.0。没有修改安装包、开场行为、长期记忆或将模糊表达统一解释为持续需求。

## 本轮行为

- 一个主讲解/教学任务，同时最多两项独立辅助需求，其中最多一项需要后台感知；其余可为定时提醒。所有观察共用现有摄像头采样，各自维护条件与完成状态，播报继续走官方单一通知队列和用户打断门槛。达到容量明确返回失败，不覆盖原任务。该限制控制并发连接和观察费用，不是无限多任务支持。
- 通话内需求使用固定 ID 和版本。辅助任务暂停恢复后，需求 ID 不变，底层观察器重新创建；修改暂停中的条件不会自动恢复。暂停定时任务冻结剩余倒计时。只取消一项不影响其他任务；不明确的目标由模型简短询问。普通追问不需要新增规划或逐轮决策模型。
- `list_requirements` 提供当前主任务、辅助需求、版本及进度；`control_requirement` 精确管理辅助需求；讲解范围/深度由 `control_scene_task` 修改。主任务外部控制必须携带 ID，避免新任务版本号相同时误收旧按钮操作。旧观察器回调、过期版本操作、重复播放回执不会推进新任务。
- 教学将 `completedSteps/progress` 与 `delivery` 分开。经过二次新片段确认或明确用户确认，先记住动作完成；下一段语音真正播完再开启下一步检查。下一句播放失败时暂停，恢复从已保留的下一步继续；最后一个动作已完成但结束语中断时，恢复只补结束语。识别结果仍依赖模型，不等于独立视觉真值。
- 观察额度耗尽时取消相关观察器并保留进度，不能靠暂停/恢复绕过额度；独立定时任务和前台对话仍受原来的总预算管理。所有新逻辑都保留总生成、观察生成、输入 usage 阈值和通话时长上限。

设计参考 [StreamVibe §4.1](https://arxiv.org/html/2610.34662#S4.SS1) 中独立意图生命周期、进度与已送达响应分开管理的思想；这是本项目的通话内适配，不是论文完整系统复现，也未接入论文的历史记忆体系。

## 时延改动与测量边界

1. 教学初始指引、手动确认后的下一步、暂停恢复等使用的内部定时器，从 1 秒改为 50 毫秒，减少 **950 毫秒的人为等待**。这是该环节的变化，不代表每次完整视频响应都快 950 毫秒。
2. 教学得到第一次肯定结果后，不再叠加固定的 2 秒复核间隔；仅在官方观察器有新两帧片段时立即尝试复核。第二次证据时间必须晚于第一次；不确定清除候选，普通检查仍间隔 4 秒。没有降低确认次数、改为单帧或提高常态云调用频率。
3. 记录 `official_latency`：用户停说到第一段音频、观察生成耗时、通知排队、开始生成到首音频、首音频到浏览器播放回执、最近证据到播放回执，以及本机检测到转镜头后的撤回命令/新讲解回执。所有跨阶段差值使用同一服务端时钟，不减去手机的绝对时间。手机另外报告本地缓冲等待。
4. 浏览器播放回执包含回程网络时间，不是扬声器声学测量；最近证据时间也不是用户动作实际完成时刻。转镜头撤回指标只到服务端清空命令，不能称为手机已经停止出声。后续手机连续测试仍需要与画面/听感对应，才能建立真正端到端基线。
5. 本地完整链路记录确认：官方 Injector 在上一段播放结束后保留约 800 毫秒安静间隔，个别通知排队耗时约 0.5–0.9 秒。本轮未修改该私有门槛，保留防抢话行为；下一轮可针对实机分布评估可配置的更短间隔，而非绕过官方队列。

汇总命令（同时支持普通文本日志和 LiveKit 的 JSON 包装日志）：

```powershell
.venv\Scripts\python.exe scripts/summarize_official_latency.py .runtime/logs/worker.log
```

输出各阶段样本数、P50、P95、最大值。少量或本地假模型样本只能检查链路与计时，不能用于声称真人视频体验已经达标。日志只留耗时和任务标识，不新增录音、图片或用户对话日志。

## 手机重点验证

刷新启动器输出的手机 HTTPS 地址并重新加入，依次验证以下场景。

1. 先让它一步步指导画画/做手工，再说“顺便三分钟后提醒我休息”。应同时保留主任务和独立提醒。
2. 途中正常追问“这一步怎么做”，再说“休息的提醒不用了”。确认只结束提醒，教学进度保留；也可用每项自己的暂停/结束按钮核对。
3. 做完当前步后，在下一段指导中插话或暂停，再恢复，检查不会丢掉已确认完成的动作。最后一步完成与结束语送达要分别看待。
4. 讲解时快速转镜头、停稳、临时问问题，比较旧内容停止速度和新主体开始速度。不要只测一次顺利路径，同时记录漏判、误判、打断后的状态和用量。

仍待实机确认：自然短句的多轮意图理解、真实绘画/手工完成识别率、手机网络与声学时延分布、相似物体身份稳定性。支持的任务数量有限，跨通话恢复、复杂任务依赖、长期记忆及自动全局持续默认不在本轮范围内。
