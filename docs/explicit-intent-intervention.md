## 实现

官方 LiveSession、工具、ProactiveScheduler、实时 Monitor 的媒体封装/连接/回收、通知队列、播放回执继续复用。通过官方 `createMonitor` 注入本地证据适配器，未修改 `node_modules`。

1. **同一次观察生成结构化证据**：返回 clip 编号、matched / not_matched / unknown、两帧各自的具体观察、状态/转变类型。用户要求、助手确认、旧画面不能作为当前对象存在的证据。无需另一次串行审核调用。
2. **保守接纳**：检查当前 clip、两帧引用、字段有效性、最新证据不超过 5 秒；unknown/无效/过期结果不触发，也不作为解除条件的 false 信号。视觉真假仍依赖模型；结构校验不是独立视觉核验，不能保证消除幻觉。
3. **转变**：必须描述有序前态和后态；跨 clip 的前态只允许引用最近 15 秒内明确 not_matched 的观察。仅保留一条通话内任务状态，不建立记忆库。单个静态终态不能凭空证明转变。
4. **持续意图**：主模型提示明确 `每次/每当` 使用 repeat=true；状态判断不因“已经提醒过”而自动 wait。官方去重规则仍有效：触发 → 条件明确解除 → 再次发生。unknown 不解除。连续在场只提醒一次；按时间间隔持续刷提醒不在本次范围。
5. **任务管理**：手机显示条件、一次/每次规则、触发/已确认播放次数、观察状态、最近判定耗时；可切换一次/每次或结束任务。修改带 generation 校验，拒绝旧页面覆盖新任务；仍使用官方更新/取消路径。修复官方快照不含 canStop 导致停止按钮缺失的适配问题。
6. **通知时效**：视觉提醒排队超过 8 秒且未开始播放则撤回；关闭/切换摄像头撤回尚未播放的视觉通知。已经开始的播放继续服从官方打断和浏览器回执。未确认播放不会增加已播放次数，页面同时显示未投递状态。
7. **诊断**：日志只记录任务 ID、代次、重复规则、状态码、计数和耗时；不记录用户条件、场景描述或原始图像。手机显示预算暂停原因，不再把额度用尽表现为悄悄只提醒一次。

## 延迟和成本

- 维持 1 FPS 和两个实际采样帧；轮询 1 秒 → 250 ms；重复冷却 3 秒 → 1 秒；窗口 10 秒 → 3 秒，减少陈旧排队。
- 显式视觉 Monitor 使用 `representation_compact=none` 保留时间边缘；纯视觉提交末尾增加 100 ms 协议静音，让末帧位于音频边界内。无需等待 100 ms 墙钟时间。这些是协议载波，不是环境音频证据。
- 首轮快速转变漏检后，同时调整末帧封装及提示格式；随后两方向样本通过。未做单变量消融，不能断言单一根因。
- Monitor 每 6 次观察回收上下文；连接总量上限 16、同时连接上限 4。观察输出仍上限 256 tokens，前台 512。
- 默认/本机试测预算调整为每通话 **40 次总生成、20 次后台生成、180 秒**；数值上限仍维持 40/20，不开放无限观察。后台包括官方文本辅助调用。后台观察在总预算剩 4 次时提前暂停，为前台保留额度；并发情况下 gateway 仍作最终硬门控。耗尽后台预算可继续对话；耗尽总预算需重新加入。
- 1 FPS 不能保证捕获一闪而过的短事件；测试时让物体出现/移出各保持至少 3–4 秒。复杂遮挡、相似物体、多阶段动作仍需真实手机评估。

## 手机试测

刷新启动器输出的手机 HTTPS 地址，重新加入并开启摄像头。每轮结束后挂断以停止计费。

1. 说“看到水杯提醒我喝水，只提醒一次”。先给无水杯画面，再放入水杯，检查只触发一次及播放状态。
2. 说“每次看到水杯都提醒我喝水”。确认面板为“每次独立事件”。持续在场不要重复说；拿出画面并保持 3–4 秒，等待“条件已解除”，再放回，应再次提醒。
3. 说“杯子从竖立变成倒下时提醒我”。先保持前态，再改变，检查不在未转变时抢先提醒。
4. 测试相似物品、遮挡、移出后快速返回、普通问答插入、规则切换、取消、关摄像头及预算暂停。

可复现命令：`npm.cmd test --prefix harness/qwen-live`、`.venv\Scripts\python.exe scripts/verify_official_harness.py`。付费探针默认不联网，显式 `--live` 才执行：`scripts/probe_explicit_intent.py`（最多 7 次，`--case transition` 最多 2 次）。
