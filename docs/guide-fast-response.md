# 讲解快速响应（2026-11-06）

## 改动

- 官方模式平时保持 1 FPS。开始讲解、用户指定主体、检测到转镜头时，采集器短暂以 4 FPS 采集，最长两秒，确认主体后提前恢复。自动触发至少间隔三秒；重复的同一视野状态不会持续延长加速。只处理真实收到的新帧，不复制缓存图片凑帧。
- 加速只进入讲解观察器。官方调度器内还有 1 FPS 限制，因此适配层直接向当前有效的讲解观察器提供新帧并尝试评估，仍由官方 Monitor 执行两帧协议、单次生成、生命周期和成本限制。普通对话、教学和辅助提醒保留常态帧通道。
- 讲解观察最多保留最新两帧，间隔至少 200 ms；第一帧最多三秒、第二帧最多 1.5 秒。等待模型时丢弃积压旧帧，进行中的生成不重叠。常态观察调用间隔 2.5 秒，寻找主体为 2 秒，未因 4 FPS 而改成每帧一次生成。
- 点选/口头纠正复用当前观察连接，只更新视野版本并清空旧待处理片段、撤回旧目标播报。旧版本正在生成的结果不能通过验证；若已有生成在途，仍需等它结束，未采用并行调用抢答。
- 点选后手机立即显示一个短暂的虚线圆提示点击位置。它不是识别成功的主体框；绿框仍需视觉确认。
- 用户开始讲解或纠正目标后的八秒内，将官方 Injector 的额外静默间隔从 800 ms 缩为 150 ms；仍遵守用户正在说话、前台生成和实际播放中的所有阻塞条件。首段讲解开始播放后恢复常态。仅使用固定版本的实例适配，不修改 node_modules，不取消用户正在听的普通回答。
- 产品提示词区分持续性、对象范围、内容深度；“讲解一下”不自动等于持续任务，“持续分析”也可建立讲解任务。这属于模型行为约束，尚非自然语音路由准确率的保证。
- 主体日志增加门槛未通过的原因；连续点选位置不匹配可以进入已有的限频询问，不必只能默等选择超时。

本轮百炼实测未完成：首次连接被沙箱网络权限阻止，之后授权网络下仍无法就绪。进一步零生成握手检查确认服务返回无 `type` 字段的 `AccessDenied.Unpurchased`（当前模型访问被拒绝），不是快速两帧被模型拒绝。各次探针均为 0 次生成、0 返回 usage；最后连接等待报告为 `.runtime/guide-target-probes/7b82e231-2bf2-4780-a470-64090d2e67bd.json`。探针最多四次生成的限额未消耗。仅凭该错误无法断言是欠费、未开通还是空间权限配置变化；需要账号侧核实。适配层已将这个已知非标准错误转成明确的模型访问提示，避免长时间等待。

本版仍需两帧视觉证据才开始持续讲解，没有改为单帧猜测或直接把点击位置视为识别结果。加速主要减少收集画面、重新连接和额外静默等待；模糊画面、弱主体的追加确认、服务网络耗时、正在进行的用户对话仍可能造成等待。
