# 连续介绍：合并串行回执等待

本轮只处理同一连接内的串行配置、输入提交和工具回填等待。未更换模型入口，未增加上一段播放时提前识别下一件的行为，未降低停留或画面核对阈值。

**验收状态：功能回归通过，五秒目标未达成。** 最终三件物品从画面切换到远端解码首音为 **7134 / 6519 / 6834 ms**，样本量 3，不代表手机听感或稳定分布。Python 132 项测试通过。保持原手机入口，服务已运行最终版本。

## 最终执行顺序

- 连接建立：确认完整配置，初始化固定工具和音频格式。
- 观察/核对：发送当前指令配置 → 发送首段 20ms 合成静音 → 图片 → 余下合成静音 → 提交输入；等待配置和输入提交两个回执都成功，再请求模型判断。
- 介绍：只有 reducer 已连续发出工具回填与对应语音命令，才合并为“发送讲解授权 → 更新语音指令 → 等待两个回执 → 请求语音”。不跨越暂停、取消或其他命令重排。
- 生成请求前重新校验请求仍有效；首音前既有画面新鲜度、场景、停留和一致性检查继续保留。

配置更新只带当前指令与 token 上限，省去固定工具和音频字段的重复提交。合成静音仍为原来的 500ms，图片仍锚定在首段 20ms 后；继续按原来的 20ms 分包发送。真实用户音频发送逻辑保持原样。

没有删掉回执，也没有在图片提交或讲解授权尚未确认时请求生成。配置发送日志标注 `phase=sent`，不能把这个零附近的发送耗时当成服务端配置完成耗时。`harness_generation` 位于真正发送生成请求前，`generate_ms` 不包含前面的回执等待。

[服务端协议参考](https://www.alibabacloud.com/help/en/model-studio/client-events)：会话更新、图片随音频提交、函数结果回填后续答。

## 验证与限制

离线测试覆盖配置等待中已上传图片、提交确认前不生成、工具和配置等待重叠、等待中暂停、缺失回执失败关闭、保守模式和最小配置更新。

真实端到端测试继续使用固定绘制物品、自然晃动、远端解码音轨首音计时。开发尝试与最终结果见同目录结构化结果文件。所有失败保留；不因功能测试通过就认为五秒目标已经达成。

最终轮通过三件连续介绍、扫动安静、静止不重复、暂停/继续/结束、任务结束后普通问答；页面异常 0，挂断后活动媒体轨道 0。结构化记录：[harness-showcase-ack-results.json](harness-showcase-ack-results.json)。

开发中尝试过在回执前请求生成并缓存输出，以及合并合成静音尾部分包；前者未证明可靠的整体时延收益，后者实测更慢，均未保留。最终仍在生成前核齐所有回执，维持原静音分包。未通过缩短语句之外的假首音、播放等待提示或提前输出未授权内容来凑目标。

测试期间原较长启动语音及任务后问答出现过输入提交超时，发生在本轮未修改的普通用户输入路径。最终另使用明确标注的较短合成请求验证展示路径；原测试请求保留，不能当成严格同条件 A/B。
