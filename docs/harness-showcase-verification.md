# 连续物品介绍原型（2026-11-02）

本轮依据用户确认的场景实现 `showcase`：说一次“接下来逐个介绍我展示的物品”，之后依据画面自动观察和简短介绍。它不要求提前知道物品清单，也不要求每件物品再提交一次语音。普通问答、用户确认的 guidance 继续保留；不据此宣布完整 H3/H4/H5 已验收。

手机实测后更新：首次原型存在二次观察绕过工具和画面变化频繁取消的问题，已改为独立布尔确认与更耐受抖动/曝光变化的过滤。当前实现和新验证见 [手机静默问题修正](harness-showcase-stability-fix.md)；下文保留首版实现及失败记录。

## 实现与初始参数

- 复用一个 Qwen 连接及既有 DECIDE/工具回填/SPEAK/服务器播放回执链路。
- 用户轮次用 `submit_task_decision`，安静展示观察用字段更少的 `assess_presentation`；两项声明在所有阶段保持固定。应用按阶段校验工具，观察提示不混入用户问答和 SPEAK 规则，未增加模型。
- 受控模式本地约 3 FPS 抽帧；32×24 缩略图像素差和 RGB 直方图差只作移动/稳定线索。允许小幅位移，同时与锚点比较以过滤缓慢移动；帧中断超过 1 秒重新累计稳定时间。
- 稳定约 1.5 秒后才可上传候选。Qwen 依据目标、当前图片、候选与已介绍历史，返回等待、明确展示、已介绍、值得补充的新细节。程序不把稳定直接等同于展示意图。
- 两次不同的采样帧，在同一稳定场景中都认定为同一展示主体，才进入简短讲解。确认观察至少在上次决定后 1 秒；无新内容则约 12 秒复查。阈值和时长都是调参初值，不是延迟保证。
- 观察每次提交新图片和 0.5 秒 `transport_silence`，显式 commit 并等待回执。合成静音不是用户语音，相关转写与讲话事件不得进入 SDK 的用户轮次和页面。
- 镜头移动使旧候选失效，并取消进行中的观察。正在播放的短讲解继续讲完，再处理最新画面；不积压沿途见到的所有物品。讲解意图限制 120 字，提示目标约 5–10 秒，不做句中硬切。
- 只有生成和 `server_playout` 都完成，才记录为已介绍。候选、被拦截的内部回答和未播完的讲解都不能算已介绍。`known` 必须引用已播放的物品 key。
- 物品外观、已讲内容历史最多保留 12 件，每件摘要有长度限制；相同物品复用 key。身份和语义去重由 Qwen 判断，未承诺长期重识别。
- 同一时间最多一个模型生成；背景观察与用户问答共用每分钟 20 次生成预算，背景预留用户交互额度，预算不足时延后观察。暂停、结束、关闭连接后不启动新观察。

可配置项：`SHOWCASE_SAMPLE_FPS`、`SHOWCASE_STABLE_SECONDS`、`SHOWCASE_RECHECK_SECONDS`、`SHOWCASE_MOTION_THRESHOLD`。保留默认 `.env` 的 legacy 模式，通过 `--harness` 子进程配置进入本轮模式。

## 自动验证

离线回归：95 项通过。新增覆盖路过画面、轻微抖动、缓慢变化、三物品连续讲解、同物去重、新细节补充、旧观察取消、播放完成与中断、暂停/继续/结束、预算退避、旧候选不能标为已讲、合成静音转写隔离、按阶段校验工具，以及配置期间的移动竞争。前端构建通过，保留既有大于 500 kB 的包体提示。

真实链路脚本：`web/tests/showcase-smoke.mjs`，隔离 Edge、固定 Windows 合成语音、canvas 绘制杯子/钥匙/书 → 真实 RTC → 当前 Qwen → RTC 音频接收。未使用物理麦克风、摄像头或扬声器。浏览器测试上下文忽略本地开发证书错误，不以此证明手机已信任证书。

报告与失败记录见 [结构化验证记录](harness-showcase-results.json)。失败不会被后一次成功覆盖：

1. 首次在隔离浏览器通过 HTTP 打开，而信令使用开发 HTTPS 证书，未能接通信令，未进行模型生成。
2. 进入 showcase 并过滤移动画面成功，但观察工具参数校验失败。保留失败；随后明确观察参数示例，并把固定的 schema 规则错误转换为可纠正的错误码，不记录用户参数值。
3. 一次完整固定媒体链路通过：一次启动，杯子、钥匙、书均自动讲解；杯子静止 15 秒不重复；暂停、继续和结束检查通过。13 次生成，其中 8 次观察；浏览器接收 RTC 音频 220616 字节；挂断后采集轨道 0。页面发现空用户消息，补充合成静音转写隔离。
4. 回归暴露模型偶尔绕过工具直接生成内部回答，虽被输出门禁挡住，随后却认为内容已讲，导致候选不再确认。本轮保留失败；强化“仅应用中已播放的 introduced 是事实”的规则，并用程序限制 known 的物品 key。
5. 仅加强提示和 known 校验仍未稳定，继续发生观察中绕过工具、随后错误引用未播放物品的情况，被拦截并暂停。保留失败；随后分离字段更少的观察专用工具及其提示，工具集合始终固定。
6. 最终版本完整通过：一次请求后自动介绍杯子、钥匙、书，移动时安静、静止 15 秒无重复，暂停/继续/结束通过。浏览器接收 RTC 音频 227613 字节，只有 1 条真实合成用户请求转写，无观察伪用户消息；页面异常 0，挂断后采集轨道 0。手机宽度截图无横向溢出。另使用项目 CA 正常验证 HTTPS 200；房间/任务/会话清理结果见 JSON。

## 手机测试

```powershell
.\scripts\start-harness-mobile.ps1
```

沿用已配置的手机 HTTPS 入口。当前配置为 `https://172.20.10.9:8443/`，电脑和手机需互通；地址随网络配置变化。

1. 刷新页面、加入通话、开启摄像头。
2. 点击“开始说话”，说“接下来逐个介绍我展示的物品，每件简单讲两句”，然后提交一次。
3. 从杯子缓慢扫过背景，再对准杯子停留；听完保持不动，观察是否重复。
4. 换到钥匙，再换一本书；后续不提交语音，留出两次模型观察和讲解的时间。
5. 测试暂停、继续、结束。需要追问或主动打断时，仍使用“开始说话/提交”按钮。

## 待真实设备验收

- 真实手持镜头的运动、曝光与抖动阈值；静止背景、多个物体、拿近展示、相似物品的展示意图区分。
- 相同实物换角度是否正确补充且不重复；现实遮挡、误认与漏讲。
- 换物到首音的延迟、手机实际听感与自然程度。当前两次判断会增加等待，不等同于稳定 1.5 秒后就立刻出声。
- 模型工具调用仍有不遵守规则的可能；最多一次纠错，失败会暂停，不用被隔离的内部回答冒充已讲解。固定绘图成功不能替代真人实物验收。
- 启动和追问仍需按键提交；自然语音端点、无需按钮的插话、自动判断操作完成不在本轮实现范围。

服务器播放完成只证明服务端音频送出，不证明手机实际听见；未以 `response.done` 代替播放结束。
