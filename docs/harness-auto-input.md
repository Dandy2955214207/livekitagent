# Harness 自动语音输入

接通后直接说话，音频在说话期间经现有 Qwen 连接上传，本地 Silero 检测说话开始及结束，不需要录音或提交按钮。默认持续静音 0.75 秒视为结束；保留麦克风开关，任务暂停/继续/结束不再自动关闭麦克风。

## 范围与顺序

仅替换输入适配层。Controller、任务策略、工具校验、DECIDE/SPEAK 分离、自动物品介绍规则及回执合并策略不变。模型连接继续关闭自动 VAD 生成，由 harness 控制所有生成请求；没有新增云端 STT/TTS 或第二个问答模型。

1. 本地语音检测确认开口后，发送原有 `user_started` 事件。旧生成和播放按原有规则取消，再开始上传本次音频。
2. 保留约 300ms 开口前音频，后续音频持续上传。静音等待不创建模型轮次。
3. 说完后绑定最新有效画面，提交已上传音频并等待回执。只发送一次原有 `user_turn`，使用已提交引用，避免再次上传整段音频。
4. 后续仍为内部判断 → 工具回填 → 语音回答；这部分等待没有因取消按钮而消失。

暂停/结束会丢弃未完成输入。已上传但未提交的残留，在新语音或下一次画面观察前清空。旧提交回执晚到时不能触发新回答；画面在提交期间切换或过期时，不绑定为当前画面。单次语音最多30秒，待上传音频最多5秒，VAD积压最多3秒；超过限制停止或暂停，不无限缓存或自动重放。

Silero 与当前 LiveKit Agents 同为 1.8.9，ONNX 模型随包本地运行。插件在主线程注册，模型加载在线程中完成，并在连接云端模型前结束，避免首次导入阻塞接收循环。[插件说明](https://docs.livekit.io/agents/logic/turns/vad/)。

## 体验边界与回退

语音活动检测按停顿断句，较长句中停顿可能被当成结束；手机外放回声和真实噪声仍需实机体验。页面保留回声消除、降噪和自动增益设置。断流/麦克风关闭时用本地静音结束当前语音边界，避免一直停在听取状态。

`HARNESS_END_SILENCE_SECONDS` 可调整静音阈值，范围0.4–2秒。`HARNESS_AUTO_INPUT=false` 并重启恢复原开始说话/提交按钮，不改变 harness 内部逻辑。兼容沿用 `controlled_manual` 模式标识，自动输入状态另由 API/任务状态说明。

手机仍使用原 HTTPS 入口，刷新后重新加入通话。具体测试记录见 `harness-auto-input-results.json`；自动化合成媒体不能代替手机回声、句间停顿或打断的实机验收。

## 本轮验证

- Python 141 项通过，前端构建通过（保留既有大包提示）。测试覆盖真实 VAD 初始化与静音不触发、开口前音频、结束前上传、只提交一次、暂停丢弃、旧提交晚到、新语音打断旧生成、提交期间换镜头、输入/VAD 积压限制及关闭清理。
- 固定合成媒体经过真实 RTC 和现有模型，普通自动问答单独完整通过：不操作录音/提交、静音不触发、最终收到回答，零页面异常，挂断后轨道为0。
- 两次真实自动启动 showcase，三件物品讲解、扫动安静、静止不重复、暂停/继续/结束等七个交互检查通过。完整脚本均因任务结束后的问答超时标为 failed，不能称为全套通过。最终轮这次追问已自动上传、产生内部决定并收到语音首包，但没有在脚本期限内完成整轮；原因未确定，未修改内部生成/回执规则绕过。
- 开发期间服务尚未启动、插件注册线程不符合 SDK 要求等失败也保留。线程注册问题已修复，真实 VAD 启动新增回归用例；测试没有使用物理设备。
- 最后清理检查：测试房间0、worker活动任务0、API活动会话0。原手机入口继续运行自动输入版本，真实手机验收待用户进行。
