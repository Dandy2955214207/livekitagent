# D2 接线与真实媒体验证增量

日期：2026-11-02（Asia/Shanghai）。状态：**独立文字观察已接线，组件样例通过；浏览器 RTC 整链路未通过，语音提醒未开放。** 此文更新此前 D2 本地骨架记录，不将前置组件测试等同完整 D2 验收。

## 已实现

前台仍使用原 M2 自动语义轮次和直接语音回答，没有增加每轮 DECIDE/SPEAK。独立 BackgroundObserver 从已编码图像缓冲读取新帧，单独启动 QwenMonitor；无观察任务不建立 Monitor 连接。UI 可创建、更新、暂停、继续、取消观察，结果只显示文字。Monitor 不输出语音，不改前台上下文，不执行任务工具。

任务/镜头变化取消旧推理并清空在途证据；重新开始只使用新画面。慢推理只保留最新待处理片段，连接准备完成及真正发送前可以重取最新帧，最终结果绑定的 frame_ids 就是实际发送的帧。没有把推理前旧帧的来源贴到新画面上，也没有放宽五秒新鲜度门槛。一个任务不逐次重复配置系统提示，条件 revision 改变才更新。

一次 matched 接受后任务 completed，关闭 Monitor，文字报告立即推送；报告过期后标为历史观察。文字显示不标记语音 delivered，不写入“已听到”记忆。历史观察只进入有界本通话文本缓冲；用户手动事实/纠正和显式持久库沿用前一轮实现，尚未回注模型。

预算按通话保留，暂停/修改/换镜头不会清零。默认最多十次后台尝试，可用 `BACKGROUND_MAX_GENERATIONS_PER_CALL` 设置 1–20；仍有每分钟二十次、单次十秒和连续失败暂停限制。预算用尽显示明确暂停原因，普通问答继续。配置/生成失败不增加另一条语音链路。

功能默认关闭：`BACKGROUND_OBSERVATION_ENABLED=false`。只有当前已测的一步 API + `qwen3.8-omni-flash-realtime` 可显式启用实验文字观察，不能把结果赋给其他提供商或模型。M2/H2 入口及默认模式保持不变。

```powershell
# 默认直接问答 + 本地记忆，观察保持暂停
.\.venv\Scripts\python.exe scripts/run_local.py --direct-background --mobile
# 显式实验文字观察；仍没有语音提醒
.\.venv\Scripts\python.exe scripts/run_local.py --direct-background --observe-text --mobile
```

实验模式仍须在面板点击“开始文字观察”才产生后台模型用量。没有重启用户现有手机服务；本轮 RTC 测试用独立 API 8001、Worker 8082、专用 Agent 名称和隔离房间，结束后只回收自建资源。

## 协议探测结果

| 批次 | 固定输入与上限 | 结果和边界 |
| --- | --- | --- |
| primed-event 初次 | 最多两轮、150 秒 | 收到供应商事件前连接超时，生成零；不能判为接口不支持 |
| 带强制复述历史 | 原 greeting 合成语音，最多两轮 | 两次语音完成，但第二次重复“语音测试成功”，未表达报告，发声检查 failed；1614 reported tokens |
| 中性问候历史 | 新合成“你好，我们做一次观察提醒测试”，最多两轮 | 新 instructions 精确回显；第二次确实说出“红色圆形已出现”，原语音模态保留；1675 reported tokens。只证明有历史的手动连接可走这条原语，不证明自动轮次竞争可靠 |
| 薄调度组合 | semantic_vad/create_response=false/interrupt_response=true；最多三轮、100 秒 | 真实 commit 后不自动生成，显式一次用户回答；快照后字段保留，后续用户语音可再提交并回答。2546 reported tokens。报告生成没有正确引用红色信息，事件响应为 completed；不能宣称事件表达、实际取消或 SDK 播放竞争通过 |
| response.instructions | 最多两轮、150 秒 | 暖场生成已开始但等待完成超时，还没执行到 response 级覆盖；生成一轮，清理阶段最终收到了836 tokens的usage，不据此判断字段是否支持 |

薄调度字段仅作为 QwenClient 可选参数加入，旧 M2 配置不带这些字段，当前运行时也没有启用薄调度。探针旧文件的 `passed_fixed_scheduler_probe` 只覆盖提交/单次请求这些控制原语，没有校验报告内容或实际播放中断，完整 P0-E 仍为 unknown；后续脚本已将状态命名收窄。

方案参考 [官方 daemon 开发说明](https://github.com/QwenLM/Qwen-Live-Harness/blob/main/packages/qwen-live-harness/README.md) 的独立 Monitor 与薄调度职责；[客户端事件文档](https://help.aliyun.com/zh/model-studio/client-events) 用于核对更新、提交与生成顺序。未将官方参考实现当作一步 API 的兼容证明。

## 应用组件与 RTC 验证

应用级绘制钥匙图（不接 RTC）的首轮最多两次生成，没有产生可接受事件，预算用尽暂停，907 reported tokens。补上连接准备后绑定新帧、减少重复配置后，第二轮**一次生成完成**：识别灰色钥匙图标、事件有真实帧来源、结果年龄 4453ms、任务 completed、只显示文字且没有语音回执，334 reported tokens。初次报告没有足够细的帧龄诊断，因此不将其根因写成已证实；后续增加了帧龄与 stale_results 指标。

RTC 测试脚本为 `scripts/verify_direct_background.py` + `web/tests/direct-rtc.mjs`，只用 Canvas 绘制钥匙和本地合成语音，没有物理设备。

1. 首轮等待文字结果超时，未执行后续问答。观察阶段缺少完整用量/帧龄记录，保留 failed，未推断成功。
2. 增加即时推送及诊断后，识别完成两次，但结果年龄分别 **5125 / 5578ms**，超过五秒门槛，均拒绝投递，随后按两次测试预算暂停。911 reported tokens。前台音频和图像输入仍在流动，但未执行到 QA 验收步骤，因此不宣称并发问答通过。
3. 再增加实际发送前取最新帧及准确 ID 的修正后，复测在浏览器等待接通阶段超时，未进入观察/问答。这个最终修正离线验证通过，**没有真实 RTC 成功证据**。

没有通过改大帧龄阈值、把历史观察包装为当前报告、伪造首音/播放完成或删掉失败样本来凑通过。当前仍不宜作为可靠手机自动提醒使用。完整 RTC、前台并发性能、实物正负例、语音来源/抢占/播放关联和记忆回注均待验，暂不增加付费大回归。

## 检查、成本与清理

最终 175 项 Python 回归、前端生产构建、390px 离线 UI 操作检查通过；保留原有包大小提示。新增覆盖连接准备时换成最新证据的实际 frame_ids、暂停取消及预算不重置、无任务不推理、镜头关闭保留目标、一次文字事件立即推送、原 M2 配置不受薄调度可选字段影响。控制台/Worker 增加的后台指标只有计数、用量与耗时，不记录原图、音频或完整个人记忆。

本开发轮已返回的用量合计 **8823 tokens（输入 8148、输出 675）**，是可核对的下限，不是账单总额：第一轮 RTC 缺少完整 usage，部分连续上传输入和连接也可能计费。账户实际单价未验证，不估算人民币费用。超时请求在关闭期间返回的 usage 也计入总数，不因未进入成功响应列表而漏计。每组有明确次数/时限；没有自动无限重试，最终停止追加付费复测。原始失败及成功结果都保存在 `.runtime/direct-background-probes/` 和 `.runtime/direct-background-rtc/`；同名 JSON 列出精确路径与每组预算。

三组隔离 API/Worker 子进程均已退出。日志中明确派发的两个测试房间在清理检查前已无残留；没有删除既有手机房间或停止原有服务。第三组没有完成接通。原始媒体未落盘，新增中性问候 WAV 只是明确生成的非真人测试 fixture。

下一步应先解决 RTC/网络下的稳定接通和帧龄余量，并用最小样例验证最终发送前取帧修正；随后再接前台事件调度与真实 server_playout 关联。D3 自然语音任务和 D4 模型记忆使用仍不提前宣布完成。
